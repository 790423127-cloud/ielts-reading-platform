### 2.3 本轮直接修复的显示与题型问题

#### A. 剑雅 15 Test 1 Part 2 漏 7 题

根因：旧解析器使用 `(\$[^$]+\$)` 切分模板。正文中的字面金额 `$24 million per year` 被当成题目占位符起点，吞掉了后续 `$119857$` 至 `$119863$`。

修复：只允许当前题组中真实存在的 question ID 形成 `$id$` 占位符；普通美元金额保持正文。

验证：

```text
Part 2 真实控件：119856–119868，共 13 个
$24 million per year：保留
“_____”降级占位：0
```

#### B. 通用文章标题显示

根因：当 `article_title` 和 `source_article_title` 都是通用标题时，前端仍显示 `Passage 1/2/3`，造成标题层级突兀。

修复：

- 有可靠真实标题且正文未重复：显示真实标题；
- 真实标题已在正文原位置：不重复；
- 只有通用占位标题：不显示伪标题，不猜测题库内容。

已验证的占位标题页面包括剑雅 20 Test 1 Part 3、剑雅 20 Test 3 Part 2、剑雅 9 Test A Part 1、剑雅 8 Test A Part 1、剑雅 4 Test A Part 1。

#### C. 窄题目栏匹配题被裁切

根因：组件使用最小 260px + 360px 的两列，旧 CSS 只按整个浏览器宽度响应。浏览器很宽但右栏拖到 30% 时，媒体查询不会触发。

修复：题目滚动区改为 CSS Container Query 容器；右栏实际宽度低于 680px 时，自动切为“说明 → 题目 → 选项库”单列，取消选项库 sticky。

验证：1440px 桌面、文章 70% / 题目 30% 时，右栏约 412px，匹配题单列完整显示，无横向溢出。

#### D. 方法课程与专项训练的重复残留

核对 Git 历史后确认：两者在原合并提交中就是两个不同职责——方法课程负责固定离线讲解，专项训练负责从真实题库组题、计时、提交和服务端判分，不能删除任意一条业务链。

实际重复出现在数据层：完整17题型课程迁入后，早期 `SUBTYPE_METHODS` 简版说明仍保留，并被方法 API 与训练目录再次合并。由此形成两份题型标题、目标和步骤来源，后续修改可能不一致。

本轮修复：

- 删除早期17题型简版说明，仅保留5个真正独立的基础方法；
- 17种题型的课程目录、详细讲解和训练目标统一读取完整离线课程；
- 删除前端已无调用方的 `fetchAbilitySkills` 旧请求函数；
- 侧栏名称明确为“方法课程”和“专项训练”；
- 每门方法课直接跳转到对应题型或能力训练，不再只跳到训练首页。

### P1-06 Windows 正式构建失败

状态：**已修复，标准生产构建通过。**

根因：`next.config.ts` 在所有环境强制 `output: "standalone"`。Next.js 已完成编译、类型检查和 17 个静态页面生成，但 Windows 普通账户在复制 pnpm 依赖时需要创建符号链接，因此最后以 `EPERM` 退出；同时 Next.js 因用户目录中的另一份 lockfile 推断了错误的依赖追踪根目录。

本轮直接修复：

- Windows 默认使用标准 Next.js 生产构建，不再触发本机不具备权限的符号链接打包；
- Linux/CI 默认继续生成 standalone 部署包；
- 可通过 `NEXT_STANDALONE_BUILD=1` 在具备权限的 Windows 环境显式打包；
- `outputFileTracingRoot` 固定为本仓库根目录，不再误扫用户目录。

最终 `pnpm --dir apps/web build` 完整通过。
