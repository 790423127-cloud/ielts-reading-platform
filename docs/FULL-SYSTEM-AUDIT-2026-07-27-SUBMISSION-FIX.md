# 新版交卷修复后全系统审计与旧版对比

审计日期：2026-07-27  
新版仓库：`790423127-cloud/ielts-reading-platform`  
旧版仓库：`790423127-cloud/ielts-g-reading-ai-coach`  
修复分支：`fix/session-submit-compatibility`  
修复 PR：#12

## 一、结论

用户截图显示的不是 404，而是 **422 请求参数校验失败**。新版交卷接口已经增加兼容和可诊断修复：

- Part/单题计时字段同时兼容 snake_case 与 camelCase；
- 计时题号仍在加载服务端真实试卷后严格核验；
- 旧草稿中的无效标注、跨试卷标注或空笔记不再阻断整卷答案、判分和 Session 保存；
- 422 不再只显示“请求失败”，会返回具体字段名称；
- 增加完整40题交卷、字段别名、旧标注兼容和错误信息回归测试。

审计同时发现并修复了一个更大的仓库一致性问题：自动同步把题库目录和页面声明扩展到58套，但干净 GitHub 检出只有原有46套可复现题库，剑雅4–9的12套私有文件没有提交。旧实现要求58/58全部存在，导致干净环境中整个题库、能力训练和多项API一起503。现在改为：

- 46套可复现基础题库完整时，系统正常运行；
- 本机安装剑雅4–9私有扩展后，自动使用58套；
- 缺失某一套私有扩展时，只阻止打开该套，不再拖垮其他题库；
- 侧栏题库数量读取后端实际可用数量，不固定宣称58套；
- 迁移状态同时报告目标数量、实际数量、基础题库是否完整和缺失清单。

**替代结论：**

- 作为当前单人、本机雅思阅读学习系统：修复生效并重启前后端后，可以继续使用新版；
- 作为正式多用户系统：暂时不能完全替代旧版；
- 旧版目前仍应保留为只读业务基线和数据回退源。

## 二、故障根因

### 2.1 已确认事实

1. 截图中服务端返回 HTTP 422，而不是404。
2. 前端交卷现在携带 `part_elapsed_seconds` 和 `question_elapsed_seconds`。
3. 旧后端请求模型使用 `extra="forbid"`，且不认识新增计时字段时会拒绝整个请求。
4. 旧浏览器草稿可能携带早期结构的标注；标注是附加学习数据，不参与判分。
5. 原前端无法把 FastAPI 默认的校验错误数组转换为可读提示，只显示通用422。
6. GitHub干净检出缺少剑雅4–9的12个私有题库文件，但题库清单声明58套。

### 2.2 最可能触发截图故障的组合

- 浏览器前端、正在运行的后端和旧草稿来自不同代码阶段；
- 前端发送了新计时字段或恢复了旧格式标注；
- 后端严格请求模型在进入判分前返回422；
- 页面没有显示实际失败字段。

由于截图没有包含浏览器 Network 请求体和后端日志，无法证明究竟是哪一条字段首先触发，但本次修复覆盖了这两条最直接、可复现的协议风险，并保留核心业务校验。

## 三、修复边界

### 已改变

- 附加标注逐条校验；坏数据被忽略并记录警告；
- 计时字段兼容两种命名；
- 非法题号和Part仍在真实试卷范围内检查；
- 422错误结构统一并可读；
- 题库运行时按实际存在文件提供内容；
- CI失败时保留完整Pytest日志。

### 未改变

- 标准答案不进入公开题目接口；
- 得分和Band仍由服务端确定性计算；
- 未提交练习不返回答案和解析；
- 非法答案结构仍返回422；
- 未知题号计时和未提交Part计时仍返回400；
- Session幂等提交规则不变；
- 没有调用千问、DeepSeek或OpenAI；
- 没有迁移、删除或修改真实学习数据库；
- 没有部署或自动重启用户电脑上的进程。

## 四、新旧系统对比

| 维度 | 旧系统 | 新系统当前状态 | 结论 |
|---|---|---|---|
| 架构 | FastAPI单体 + 静态JS + 多版本运行时补丁 | Next.js App Router + React + FastAPI分层 | 新版长期维护明显更好 |
| 路由 | Hash Router、按钮模拟导航、多个恢复守卫 | Next.js唯一URL路由 | 新版更清楚 |
| 判分 | 成熟确定性判分 | 服务端确定性判分、答案隔离、幂等Session | 基本对等，新版边界更强 |
| 题库 | 长期运行题库，旧工作区拥有真实内容 | 干净基线46套；本机私有扩展可达58套 | 新版已修复“私有扩展拖垮全库”问题 |
| 模考 | 功能成熟，异常恢复和草稿机制积累较多 | 完整模考、Part、暂停、帮助、分隔线、草稿和历史 | 主要功能已迁移，真实设备仍需复验 |
| 17种专项 | 成熟的真实Part专项、难度和同题型验证 | 已有17种题型专项、真实题组和能力训练 | 当前已迁入，不再属于缺失项 |
| 原错题返回 | 保存Session/Question并自动定位 | 已有精确原题重做、方法和能力跳转 | 当前已迁入 |
| 错题批量训练 | 成熟 | 已支持按数量、Part和计时模式组卷 | 基本对等 |
| 方法课 | 17门详细离线课程 | 5门基础 + 17种题型详细固定课程 | 当前新版已补齐且不调用AI |
| 学习计划 | 后台规则成熟 | 至少8题、跨日达标、第3天复习、AI不可改掌握 | 基本对等 |
| 长难句 | 固定训练、我的句子 | 审核训练、个人句子、来源、权限和AI解释 | 新版边界更清楚 |
| 阅读标注 | 高亮、笔记和草稿 | 稳定定位、Session持久化、历史恢复、词汇连接 | 新版数据结构更完整 |
| 词汇本 | 不含完整词汇本/SRS | 去重、多来源、编辑、状态、CSV/TXT/JSON | 新版明确领先 |
| AI自由追问 | 旧版重点是逐题自动讲解，不是自由聊天 | 错题、句子和计划的证据约束自由追问 | 新版领先 |
| AI批量任务 | 动态分批、恢复、单题重试、总结和学生反馈成熟 | 当前缺少同等持久批量任务队列 | 旧版领先 |
| 教师作业 | 正式教师流程和报告形式较多 | 本机作业、关联Session、确定性报告和快照 | 新版只完成本机闭环 |
| 报告 | PDF/DOCX和历史能力成熟 | 阶段报告、浏览器打印PDF；正式报告标志仍为false | 旧版正式交付能力领先 |
| 历史数据 | 已有真实长期学习数据 | 有预览、备份清单和回滚迁移工具，尚未正式执行 | 旧版仍是数据权威源 |
| 测试 | 有浏览器Playwright与长期回归 | 后端CI强；前端主要为源码结构测试和构建 | 真实浏览器自动化旧版暂时更强 |
| 性能 | 静态资源多、全局观察器和watchdog多 | 路由和生命周期更清楚，但缺统一基准 | 新版架构潜力更好，数值未证实 |
| 多用户安全 | 单用户产品，云运行经验更多 | 有user_id但无认证，前端仍使用owner | 两者都不能直接公开多用户使用 |

## 五、问题清单

## P0：正式替代旧版前必须解决

### P0-01 账号、认证与权限

- 新版API仍允许请求自行携带 `user_id`；
- 没有可信登录会话证明当前用户身份；
- 教师、学生和管理员权限没有正式隔离；
- 当前适合单人本机，不适合不可信多用户公开访问。

### P0-02 真实学习数据迁移未执行

- 迁移工具已有预览、目标库备份、清单和回滚；
- 尚未对真实旧数据库进行试导入、数量核对、抽样核对和回滚演练；
- 旧版仍是历史成绩、错题和教师数据的权威来源。

### P0-03 生产备份与恢复

- 新版主要使用本地SQLite；
- 没有经过验证的生产数据库、多实例写入、自动备份和恢复时间目标；
- 切换前必须完成真实备份和恢复演练。

### P0-04 修复需要重启或重新部署

- GitHub代码修复不会自动替换电脑上已经运行的旧后端进程；
- 用户本机必须更新代码并同时重启新版Web和API；
- 若只更新前端或只更新后端，仍可能出现协议版本错配。

## P1：主要能力差距

### P1-01 正式教师系统不完整

新版只有本机单用户闭环，仍缺：

- 班级与学生账号；
- 发布、提交、批改和通知；
- 截止时间权限；
- 审计日志；
- 正式DOCX模板。

### P1-02 AI批量任务弱于旧版

新版有安全自由追问、缓存、token记录和每日限制，但仍缺旧版成熟的：

- 全部错题批量生成；
- 后台任务持久化；
- 中断恢复；
- 单题重新生成；
- 综合总结；
- 学生确认真实错因；
- 已理解/继续复习反馈。

### P1-03 浏览器验收没有进入CI

- 当前CI运行TypeScript、源码结构测试、Next构建和Pytest；
- 没有Playwright端到端考试交卷；
- 没有390px真实触控选词；
- 没有视觉快照和axe无障碍检查；
- 本次截图类问题本应由端到端交卷测试更早发现。

### P1-04 私有扩展题库的交付流程未标准化

- GitHub不能提交受保护题库正文是合理边界；
- 但需要有明确的本机安装、哈希核对、版本同步和缺失提示流程；
- 不能再让索引、页面和实际文件数量各自独立变化。

## P2：质量与性能问题

### P2-01 共享协议未被编译器强制使用

- 仓库有 `packages/contracts`；
- Web仍在 `lib/api.ts` 重复定义传输类型；
- 前后端字段变更存在再次错配风险；
- 建议由OpenAPI生成类型或让Web直接依赖共享契约。

### P2-02 前端组件继续膨胀

- `ExamWorkbench` 已承担题库、草稿、计时、布局、题型控件、结果和历史等多种职责；
- 自动同步一次改动超过千行，审查和回归风险高；
- 应拆成计时、草稿、题型控件、考试布局和结果模块。

### P2-03 缓存策略过于保守

- 前端API统一使用 `cache: no-store`；
- 题库目录、方法课等稳定数据也会重复请求；
- 应区分稳定内容、个人记录和实时交卷。

### P2-04 标注层仍有全局监听和周期同步

- 根布局长期挂载选区事件；
- 标注曾使用周期扫描本地草稿；
- 应只在阅读原文存在时启用，并改为事件驱动同步。

### P2-05 页面正文仍有部分固定58套文案

- 侧栏已改为后端实际数量；
- 题库工作台和能力训练的介绍性文字仍以58套为目标环境编写；
- 在只有46套基础题库的干净环境中可能产生文案与实际数量不一致；
- 应统一从题库状态接口渲染。

### P2-06 无统一性能基准

尚未在同一电脑、同一浏览器、同一数据下测量：

- 首屏；
- 题库加载；
- Part切换；
- 输入延迟；
- 交卷延迟；
- 内存增长；
- Lighthouse和Core Web Vitals。

因此只能确认新版架构更容易优化，不能声称实际性能已经全面超过旧版。

## 六、UI审计

### 新版优点

- URL和导航来源唯一；
- 当前页高亮由Next路由决定；
- 导航已经补充历史、报告、老师、诊断和帮助；
- 移动端有菜单；
- 考试区支持暂停、帮助、字号和左右比例；
- 题型控件更结构化；
- 结果页明确服务端判分和Band边界；
- 词汇、句子、计划和AI入口更加统一。

### 旧版仍然更成熟的部分

- 长期使用积累的机考异常恢复；
- 更完整的浏览器自动化和移动端验收；
- 教师和报告的正式交付形态；
- 批量AI任务进度、失败恢复和反馈流程。

### 新版UI剩余风险

- 最新自动同步修改了大量CSS和考试组件，虽然构建通过仍需要真实浏览器复验；
- 390px手机长按选词、软键盘和底部工具栏尚无CI覆盖；
- 题库数量文案没有全部动态化；
- 键盘全流程、读屏和颜色对比没有系统报告。

## 七、AI审计

### 新版更好

- AI上下文由服务端从已交卷Session、已保存句子或学习计划构建；
- AI不能改答案、得分、Band、任务或掌握度；
- 模考未交卷句子被锁定；
- 相同问题可精确缓存；
- 有对话、token、请求次数和每日限制；
- 支持千问、DeepSeek和OpenAI后端适配；
- 无证据时要求明确说明不足。

### 旧版更好

- 全部错题批量生成；
- 分批保存；
- Serverless中断恢复；
- 单题重试；
- 综合总结；
- 错因确认；
- 理解状态反馈。

### 结论

新版AI的安全性和自由追问能力更强；旧版的自动化错题处理流水线更成熟。最佳方向是把旧版批量任务能力迁入新版后端，而不是恢复旧版前端补丁架构。

## 十、最终建议

1. 合并交卷兼容修复后，前端和后端必须一起更新并重启；
2. 首先在剑雅5 Test A恢复原草稿，再次交卷，确认生成Session结果；
3. 查看 `/api/v1/question-bank/migration-status`，确认本机 `found_tests=58`；只有46时说明剑雅4–9私有扩展未安装完整；
4. 在真实数据迁移完成前保留旧系统和旧数据库只读副本；
5. 下一阶段优先做Playwright真实交卷、认证权限、数据库备份恢复；
6. 不再通过一次超大自动同步同时改UI、题库索引、API协议和测试，应拆成可审查的小PR。

最终状态：**新版个人本机使用可继续推进；正式全面替代旧系统仍需双系统并行。**
